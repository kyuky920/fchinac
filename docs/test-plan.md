# 테스트 계획서

## 1. 목적과 환경

기능 요구사항의 인수 조건과 배포 전 회귀 테스트 범위를 정의한다. 기본 테스트는
운영 서버가 아닌 로컬 Next.js standalone과 `fchinac_dev` MariaDB에서 수행한다.
합성 테스트 계정은 `example.invalid` 이메일을 사용하고 테스트 종료 후 제거한다.

## 2. 자동 검증

```sh
corepack pnpm typecheck
corepack pnpm lint
corepack pnpm build
```

CI에서는 MariaDB 11.4에 마이그레이션을 순서대로 적용하고 위 검사를 반복한다.

## 4. 배포 전 수동 점검

- Chrome·Safari 최신 버전 PC 레이아웃
- iPhone·Android 폭에서 메뉴, 로그인, 회원가입 폼
- 한국어·영어·중국어·몽골어·스페인어 문구 줄바꿈
- 기존 회원 표본 계정 로그인
- 관리자 승인·차단·권한 변경
- 게시물 목록·상세와 HWP/PDF/DOC 첨부파일 다운로드
- YouTube 링크와 임베드
- 404, 권한 없음, DB 연결 실패 시 개인정보 미노출
- Cloudflare 프록시 상태에서 실제 접속 IP·HTTPS·쿠키 확인

## 5. 릴리스 기준

- typecheck, lint, production build가 모두 성공해야 한다.
- 심각도 높음·치명적 결함이 없어야 한다.
- 마이그레이션을 새 DB와 백업 복원 DB에서 각각 성공해야 한다.
- 회원·게시물·첨부파일 수량 검증 결과가 이전 보고서와 일치해야 한다.
- 배포 전 DB·첨부파일 백업과 원복 절차를 실제로 한 번 수행해야 한다.
