# 데이터베이스 분석 및 신규 설계

## 1. 레거시 분석 요약

분석 대상은 로컬의 `legacy_import`이며 운영 서버에는 접근하지 않았다.

| 영역 | 결과 |
|---|---:|
| 회원 | 382명 |
| 게시판 정의 | 9개 |
| 게시물 | 50건 |
| 댓글 | 0건 |
| 첨부파일 레코드 | 42건 |
| 첨부파일 실물 | 42건 모두 존재 |
| 레거시 테이블 | 142개, 전부 MyISAM |

### 회원

- 등급 분포: 1등급 3명, 2등급 375명, 5등급 3명, 10등급 1명
- 탈퇴 표시 회원 1명, 차단 회원 0명
- 이메일 없는 회원 3명, 중복된 비어 있지 않은 이메일은 없음
- MySQL 4.1 비밀번호 해시 380건, 비밀번호 값이 비어 있어 재설정이 필요한 계정 2건
- 휴대전화 102건, 전화번호 359건, 주소 102건, 생년월일 37건 보유
- 기존 IP 주소와 불필요한 인증 임시값은 기본 이전 대상에서 제외한다.

### 게시판

- 게시판마다 `g5_write_{게시판키}` 테이블이 생성되는 구조다.
- 9개 쓰기 테이블의 컬럼 구조는 완전히 동일하다.
- 실제 데이터는 5개 게시판에만 존재하며 모두 회원 작성 게시물이다.
- 댓글, 비회원 글, 비밀글은 없고 50건 모두 HTML 본문이다.
- `g5_board.bo_count_write` 값과 실제 건수가 일치하지 않아 카운터는 이전하지 않고 재계산한다.
- 게시판 접근 등급 숫자는 역할 기반 권한으로 변환한다.

### 첨부파일

- HWP 18개, PDF 16개, DOC 8개다.
- 42개 레코드 모두 대응하는 실제 파일이 존재한다.
- `book_data`의 첨부파일 4건은 부모 게시물이 없어 자동 연결할 수 없다.
- `book_old` 파일 1건은 DB 기록보다 실제 파일이 54바이트 작다. 실제 파일을 기준으로 크기와 SHA-256을 다시 기록한다.
- 원본 파일명은 표시용으로만 사용하고 저장 키에는 사용하지 않는다.

## 2. 신규 모델

### 회원과 권한

- `users`: 로그인 식별자, 비밀번호 해시 유형, 상태, 기본 언어
- `member_profiles`: 이름, 거주 국가, 성별, 전화번호, 주소 등 선택적 개인정보
- `user_consents`: 이메일·SMS·프로필 공개 동의
- `roles`, `user_roles`: 숫자 등급 대신 역할 기반 권한
- `auth_sessions`, `auth_login_attempts`: 해시 기반 세션과 로그인 실패 제한
- `password_reset_tokens`: 30분 유효 일회용 비밀번호 재설정 토큰 해시
- `user_audit_logs`: 가입, 상태·권한 변경, 비밀번호 재설정 감사 이력
- 기존 MySQL 4.1 해시는 호환 검증 후 첫 로그인 성공 시 bcrypt cost 12로 즉시 재해시한다.

신규 가입자는 `status='pending'`과 `member` 역할로 생성한다. 필수 약관 및
개인정보 동의는 `user_consents.terms_accepted`, `privacy_accepted`, `age_confirmed`와 동의한 문서 버전에 기록하며
관리자 승인으로 `active`가 된 뒤 로그인할 수 있다.

레거시 등급의 초기 매핑은 다음과 같다.

| 레거시 등급 | 신규 역할 |
|---:|---|
| 1 | `restricted` |
| 2 | `member` |
| 5 | `editor` |
| 10 | `admin` |

탈퇴 표시가 있으면 등급과 무관하게 `users.status='withdrawn'`으로 이전한다.

### 게시판과 다국어

- `board_groups`, `boards`: 게시판 구성과 운영 설정
- `board_group_translations`, `board_translations`: 언어별 이름과 설명
- `board_role_permissions`: 역할별 목록·읽기·쓰기·댓글·첨부·관리 권한
- `lecture_notes`는 공개 목록·본문, 회원 다운로드, 관리자 전용 작성·첨부·관리 권한을 사용한다.
- `posts`: 모든 게시판의 글을 하나로 통합한 언어 중립 레코드
- `post_translations`: 언어별 제목·본문·번역 상태
- `comments`: 댓글과 대댓글
- `categories`, `category_translations`: 게시판별 다국어 분류

기존 글은 `ko` 원문으로 이전한다. 번역은 같은 `post_id` 아래 별도의 locale 행으로 저장하므로 URL과 조회수, 첨부파일은 언어 간 공유된다.

### 화면 다국어

- `locales`: 언어 코드, 현지어 이름, 국기, 활성·기본 여부와 대체 언어
- `site_translations`: `(locale_code, message_key)` 단위 화면 문구
- 번역 조회는 요청 언어, 지정 대체 언어(기본 영어), 한국어 순서로 처리한다.
- 언어 전체 JSON 등록은 하나의 트랜잭션에서 처리한다.

### 첨부파일과 동영상

- `attachments`: 로컬 또는 R2/S3 저장소의 파일 메타데이터
- 저장 키는 충돌이 없는 내부 키를 사용한다.
- 파일 크기는 복사 후 실제 크기로 기록하고 SHA-256을 계산한다.
- 다운로드는 애플리케이션 권한 검사 후 제공한다.
- `media_embeds`: 게시물에 연결된 외부 미디어를 저장한다.
- `lecture_categories`, `lecture_category_translations`: 6개 강의 분류와 언어별 이름
- `lecture_courses`, `lecture_course_translations`: 과목 코드, 공식 YouTube 재생목록, 언어별 과목명
- `lecture_lessons`: 차시 순서, 선택적인 개별 영상 ID, 노출·재생 상태
- `admin_audit_logs`: 게시물·파일·게시판·강의의 관리자 변경 이력
- 기존 6개 분류와 48개 과목은 유지하고, 과목별 차시에서 ABCMISSION 공식 YouTube
  재생목록을 `youtube-nocookie.com` 플레이어로 내부 재생한다. 공개 영상이 아직 없는
  차시는 외부 검색으로 보내지 않고 `영상 준비 중`으로 표시한다.

## 3. 데이터 이전 규칙

1. `g5_member`를 `users`, `member_profiles`, `user_consents`, `user_roles`로 분리한다.
2. 빈 이메일은 `NULL`로 변환한다.
3. `0000-00-00` 날짜는 `NULL`로 변환한다.
4. 원본 MySQL 4.1 해시는 `password_scheme='mysql41'`로 구분하며 첫 로그인 성공 시 bcrypt로 전환한다.
5. `g5_group`과 `g5_board`를 그룹·게시판·역할 권한으로 변환한다.
6. 9개 `g5_write_*` 테이블을 `posts`와 `post_translations`로 합친다.
7. `wr_option`의 HTML 여부는 `body_format='html'`로, 비밀글 여부는 `visibility='private'`로 변환한다.
8. 게시판 카운터는 이전하지 않고 신규 데이터에서 계산한다.
9. 첨부파일은 부모 글이 확인된 38건을 자동 이전한다.
10. 부모가 없는 4건은 `migration_issues`에 기록하고 관리자 판단 후 연결하거나 보관한다.
11. 파일 크기와 SHA-256은 실제 파일에서 다시 계산한다.
12. 원본 ID 연결은 `legacy_*` 컬럼과 `migration_map`에 보존해 반복 이전과 검증을 가능하게 한다.

## 4. 보안·개인정보 원칙

- IP 원문은 이전하지 않으며 필요 시 애플리케이션 비밀키를 사용한 해시만 저장한다.
- 전화번호·주소·생년월일은 실제 운영 필요성이 확정된 항목만 이전한다.
- DB 계정은 애플리케이션, 마이그레이션, 백업 역할을 분리한다.
- 첨부파일 경로를 직접 공개하지 않고 다운로드 API를 통과시킨다.
- 탈퇴 회원 데이터는 보존 정책 확정 후 익명화 또는 삭제한다.
- SQL 덤프와 실데이터는 Git에 커밋하지 않는다.

## 5. 배포 호환성

- 스키마는 MariaDB 11.4 이상을 대상으로 한다.
- 모든 신규 테이블은 InnoDB와 `utf8mb4`를 사용한다.
- 로컬 MariaDB 12에서 개발하고 GitHub Actions의 MariaDB 11.4에서 마이그레이션을 검증한다.

## 6. 로컬 이전 결과

`database/migrate-legacy-local.sh`을 연속 두 번 실행해 동일한 결과가
나오는 것을 확인했다.

| 대상 | 이전 결과 |
|---|---:|
| 회원 | 382 |
| 회원 역할 | 382 |
| 게시판 그룹 | 2 |
| 게시판 | 9 |
| 게시판 역할 권한 | 45 |
| 게시물 | 50 |
| 한국어 원문 | 50 |
| 댓글 | 0 |
| 첨부파일 | 38 |
| 레거시 매핑 | 481 |

검증 결과 MySQL 4.1 해시 380건이 보존되고 빈 비밀번호 2건은 `reset_required`로 분류됐으며 게시물 작성자와 첨부파일
외래키 누락은 없다. 복사된 첨부파일 38건의 실제 크기와 SHA-256도 DB 값과
모두 일치한다.

이전 이슈는 총 7건이다.

- 부모 게시물이 없는 첨부파일 4건
- 지원하지 않는 형식의 생년월일 2건
- DB 기록과 실제 크기가 54바이트 다른 첨부파일 1건
