# 홈페이지 갱신 요구사항 명세서

## 1. 목적

기존 `fchinac.org`의 화면 정체성과 콘텐츠를 유지하면서 회원·게시판·다국어
운영 기능을 현대화하고, 물리 서버 없이 Cafe24 호스팅 환경에서 운영 가능한
서비스를 구축한다.

## 2. 범위와 원칙

- 기존 운영 서버는 전환 승인 전까지 변경하지 않는다.
- 개발과 데이터 검증은 운영 백업으로 만든 로컬 DB에서 수행한다.
- 동영상 원본은 저장하지 않고 YouTube 링크 또는 임베드로 제공한다.
- 정적 페이지는 Next.js로 제공하고 회원·게시판·관리 기능은 MariaDB를 사용한다.
- 문구와 활성 언어는 관리자 화면에서 관리하며 신규 언어 추가에 코드 배포가 필요하지 않아야 한다.

상태 표기: `완료`, `진행 예정`, `검토 필요`.

## 3. 사용자와 권한

| 사용자 | 설명 | 주요 권한 |
|---|---|---|
| 비회원 | 로그인하지 않은 방문자 | 공개 페이지·공개 게시물 조회, 가입 신청 |
| 승인 대기 회원 | 가입 신청 후 미승인 사용자 | 로그인 불가 |
| 회원 | 승인된 사용자 | 권한이 허용된 게시판·자료 조회 |
| 편집자 | 콘텐츠 운영 담당자 | 허용된 게시판에 게시물 작성 |
| 관리자 | 시스템 운영 담당자 | 회원·언어·권한·콘텐츠 관리 |

## 4. 기능 요구사항

### 4.1 공개 홈페이지

| ID | 요구사항 | 상태 | 인수 조건 |
|---|---|---|---|
| WEB-001 | 기존 홈페이지와 유사한 PC·모바일 UI를 제공한다. | 완료 | 주요 메뉴와 하위 페이지가 반응형으로 표시된다. |
| WEB-002 | 소개, 연혁, 교수, 가입안내, 강의, 자료 페이지를 제공한다. | 완료 | 각 URL이 정상 응답하고 메뉴로 이동할 수 있다. |
| WEB-003 | 동영상은 공식 YouTube 재생목록을 사이트 내부에 임베드한다. | 완료 | 서버가 동영상 파일을 보관하지 않고 외부 검색 결과로 이탈하지 않는다. |
| WEB-004 | 비회원에게 로그인과 회원가입 진입점을 제공한다. | 완료 | PC 상단, 모바일 메뉴, 로그인 화면에서 회원가입으로 이동한다. |
| WEB-005 | 기존의 분류 → 과목 → 차시 → 강의보기 구조를 유지한다. | 완료 | 6개 분류와 48개 과목에서 내부 차시 목록 및 재생 화면으로 이동한다. |

### 4.2 회원과 인증

| ID | 요구사항 | 상태 | 인수 조건 |
|---|---|---|---|
| MEM-001 | 기존 회원의 MySQL 4.1 비밀번호 해시를 호환하고 성공 시 bcrypt로 전환한다. | 완료 | 이전된 회원이 기존 자격증명으로 로그인하고 해당 해시가 bcrypt cost 12로 갱신된다. |
| MEM-002 | 신규 회원은 필수 동의 후 가입을 신청한다. | 완료 | 신규 계정은 `pending` 상태와 `member` 역할로 생성된다. |
| MEM-003 | 관리자가 가입 신청을 승인해야 로그인할 수 있다. | 완료 | `pending` 로그인은 거절되고 `active` 전환 후 허용된다. |
| MEM-004 | 관리자는 회원을 검색하고 상태별로 조회한다. | 완료 | 아이디·이메일·이름 검색과 상태 필터가 동작한다. |
| MEM-005 | 관리자는 회원 상태와 역할을 변경한다. | 완료 | member/editor/admin 및 pending/active/blocked/withdrawn이 저장된다. |
| MEM-006 | 위험한 관리자 변경을 방지한다. | 완료 | 자기 차단·자기 관리자 해제·마지막 관리자 제거가 거절된다. |
| MEM-007 | 차단·탈퇴 회원의 활성 세션을 종료한다. | 완료 | 상태 변경 직후 해당 회원의 미폐기 세션이 없다. |
| MEM-008 | 비밀번호 초기화는 짧은 수명의 일회용 링크로 처리한다. | 완료 | 링크는 30분·1회 유효하며 완료 후 기존 세션이 종료된다. |
| MEM-009 | 회원 관련 관리 행위를 감사 로그에 기록한다. | 완료 | 가입·변경·재설정 발급·완료 이력을 조회할 수 있다. |
| MEM-010 | 회원이 자신의 프로필과 비밀번호를 직접 관리한다. | 진행 예정 | 본인 확인 후 개인정보·비밀번호를 변경할 수 있다. |
| MEM-011 | 재설정 링크를 이메일로 자동 발송한다. | 검토 필요 | 메일 발송 사업자와 발신 도메인 정책 확정이 필요하다. |

### 4.3 게시판과 자료

| ID | 요구사항 | 상태 | 인수 조건 |
|---|---|---|---|
| BBS-001 | 레거시 게시판·게시물·첨부파일을 조회한다. | 완료 | 이전된 게시물 50건과 연결된 첨부파일 38건을 조회한다. |
| BBS-002 | 역할별 목록·읽기·쓰기·첨부 권한을 적용한다. | 완료 | 권한 없는 사용자의 조회·작성·다운로드가 거절된다. |
| BBS-003 | 편집자와 관리자가 게시물을 작성한다. | 완료 | 허용된 게시판에 일반 텍스트 게시물을 등록한다. |
| BBS-004 | 게시물 수정·삭제·공지 설정을 제공한다. | 완료 | 편집자·관리자가 제목·본문·상태·공개 범위·공지 여부를 변경하고 소프트 삭제한다. |
| BBS-005 | 신규 첨부파일 업로드·삭제를 제공한다. | 완료 | 확장자·크기·개수 검증 후 웹 루트 밖에 저장하고 관리 이력을 남긴다. |
| BBS-006 | 게시판 생성·설정·권한 관리 화면을 제공한다. | 완료 | 관리자가 공개 범위, 첨부 제한과 역할별 7개 권한을 변경할 수 있다. |
| BBS-007 | 서적과 자료 목록에서 첨부파일을 바로 다운로드할 수 있게 표시한다. | 완료 | 파일명·크기·다운로드 동작이 게시물 목록에 표시된다. |
| BBS-008 | 첨부파일 다운로드는 로그인 회원에게만 허용한다. | 완료 | 비회원의 화면 진입과 직접 URL 요청 모두 파일 응답 없이 로그인 안내 또는 401로 처리된다. |

### 4.4 다국어

| ID | 요구사항 | 상태 | 인수 조건 |
|---|---|---|---|
| I18N-001 | 활성 언어를 DB에서 관리한다. | 완료 | 활성 언어가 URL과 상단 선택기에 자동 반영된다. |
| I18N-002 | 문구를 키 단위로 추가·수정한다. | 완료 | 관리자 화면의 단일 문구 저장이 즉시 반영된다. |
| I18N-003 | 언어와 번역 전체를 JSON으로 가져오고 내보낸다. | 완료 | 오류 시 전체 가져오기가 롤백된다. |
| I18N-004 | 번역 누락 시 지정 대체 언어, 영어, 한국어를 순차 적용한다. | 완료 | 신규 언어는 영어를 기본으로 사용하고 미번역 화면이 깨지지 않는다. |
| I18N-005 | 번역 검색·완료율·누락 필터를 제공한다. | 진행 예정 | 관리자가 미번역 문구를 빠르게 식별한다. |
| I18N-006 | 기존 사이트의 10개 지원 언어를 같은 순서로 제공한다. | 완료 | 한국어·중국어·몽골어·스페인어·영어·러시아어·프랑스어·포르투갈어·타갈로그어·스와힐리어가 상단 선택기에 표시된다. |
| I18N-007 | 아랍어·페르시아어·네팔어·태국어·베트남어를 추가 지원한다. | 완료 | 5개 언어가 선택기에 표시되고, 미번역 문구는 영어로 표시되며 아랍어·페르시아어는 RTL 방향을 사용한다. |

| OPS-003 | DB와 첨부파일을 자동 백업하고 복구를 시험한다. | 진행 예정 | 정기 백업과 복원 리허설 결과가 남는다. |

## 5. 비기능 요구사항

| ID | 분류 | 요구사항 |
|---|---|---|
| NFR-001 | 보안 | 신규·변경 비밀번호와 로그인에 성공한 레거시 비밀번호는 bcrypt cost 12 이상으로 저장하고 평문을 기록하지 않는다. |
| NFR-002 | 보안 | 세션 쿠키는 HttpOnly, SameSite=Lax이며 운영 환경에서 Secure를 사용한다. |
| NFR-003 | 보안 | 로그인 실패를 식별자 기준 15분 동안 5회로 제한한다. |
| NFR-004 | 보안 | Cloudflare WAF·DDoS 보호와 HTTPS를 적용한다. |
| NFR-005 | 데이터 | DB와 문자열은 utf8mb4를 사용한다. |
| NFR-006 | 호환성 | Cafe24에서 지원 가능한 Node.js standalone과 MariaDB를 사용한다. |
| NFR-007 | 가용성 | 애플리케이션은 PM2로 자동 재시작하고 헬스체크를 제공한다. |
| NFR-008 | 개인정보 | 운영 비밀·회원 원문 데이터·백업 파일을 Git에 포함하지 않는다. |
| NFR-009 | 성능 | 일반 공개 페이지는 정상 부하에서 2초 이내 초기 응답을 목표로 한다. |
| NFR-010 | 접근성 | 폼 요소에 레이블을 제공하고 키보드로 주요 기능을 사용할 수 있어야 한다. |

## 6. 출시 제외·결정 필요 사항

- 온라인 결제와 유료 강좌는 현재 범위에서 제외한다.
- 회원 이메일 인증 및 자동 메일 발송 사업자는 아직 결정하지 않았다.
- 개인정보 보유·파기 기간과 이용약관 최종 문안은 운영 주체의 승인이 필요하다.
- 운영 전환 날짜, DNS TTL 축소 시점, 장애 시 원복 기준은 배포 계획에서 확정한다.
